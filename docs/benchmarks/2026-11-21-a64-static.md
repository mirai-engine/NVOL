# NVOL's aarch64 assembly against Clang -O2: static instruction count (2026-11-21)

Item 16. QEMU runs the aarch64 library (every function against the interpreter, and the native
suites) but does not time it, and there is no ARM hardware here (PENDING 2.12, item 31). So the
only comparison with a compiler is static: the instructions of each public function in the
disassembly.

- **NVOL:** `generated/gas/nvol_aarch64_aapcs64.s`, assembled by Clang (GNU as gives the same
  bytes: `python3 -m nvol.asm.samebytes aapcs64`).
- **Clang:** `generated/c/nvol.c` with `clang --target=aarch64-alpine-linux-musl -O2 -std=c99`.
- **Tools:** Alpine clang 22.1.3; GNU Binutils 2.45.1 (`aarch64-alpine-linux-musl-objdump`).
- **Regenerate:** `python3 harness/asm/a64_static.py --md`, in Alpine.

**How to read it.**
- In the C, the kernels are inlined into each public entry. In the asm, a public function with
  a single NEON target is one `b` to it, and a wrapper may end in a tail call. Each row
  therefore counts a function together with the functions it tail-calls.
- Fewer instructions is not faster by itself: what runs is the loop.
- The length of a loop cannot be read off the layout either, because the cold exits sit before
  the loop head, inside the span of its backward branch.
- This table is a map of where to look, not a speed result.

**Below Clang:**
- `count_parity`: Clang autovectorizes the scalar head and tail of the faithful port of
  memchr's `count_raw`, which the asm does not do (the same as on x86, item 17).
- `memmem_init` and `count_raw`.
- `memchr_raw` and `first_non_ascii_raw`.

**Above Clang.** The wrapper `nvol_memchr` (16 against 12) shows the causes one at a time:

```asm
    sub sp, sp, #32              // Clang: stp x29, x30, [sp, #-32]!  (pre-index, one fewer)
    stp x29, x30, [sp]
    str x19, [sp, #16]
    and w0, w0, #255             // the callee nvol_memchr_raw extends it again
    mov x19, x1
    add x2, x19, x2              // a copy not coalesced: add x2, x1, x2 ...
    mov x1, x19                  // ... and this mov goes away
    bl L.nvol_memchr_raw
    cbnz x0, .L2                 // Clang: sub + cmp + csinv, no branch
    movn x0, #0
    b .L1
.L2: sub x0, x0, x19
```

These are the A64 gaps recorded in PENDING item 17:
- pre-indexed save and restore;
- `csel`/`csinv` for a two-way `return`;
- coalescing of a copy whose source is still live;
- extending a narrow argument only once along a call chain.

The byteset family (+25…+53 %), memmem (+34 %) and Teddy (+36 %) go into the same item, with
their loops compared by hand. The cycles wait for ARM hardware (item 31).
