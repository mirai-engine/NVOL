## Counters (`tedcounters.sh`, WSL2 Alpine, same i5-7400)

The wall-clock A/B on Windows varies ±1-12 % between runs. In one run, 64 Fat patterns with 4 KiB
gave −12 %; in the next, −0.2 %. `tedcount nvol|aho CASE SIZE N` runs one `tedbench` case N times.
`tedcounters.sh` measures it with `perf stat`, subtracts the N = 0 run and takes the minimum of 3.
Per call (positive = NVOL better, in cycles):

| case | 4 KiB instr nvol / aho | 4 KiB cycles | 64 KiB cycles | 1 MiB cycles |
|---|---|---|---|---|
| 0: 2 pats m=4 Slim | 4421 / 4571 | +0.6 % | +0.1 % | −0.8 % |
| 1: 8 pats m=3 Slim | 3327 / 3493 | +0.9 % | +0.1 % | +0.7 % |
| 2: 16 pats m=1 Slim | 1472 / 1612 | +1.1 % | +3.3 % | −0.7 % |
| 3: 16 pats m=2 Slim | 2447 / 2604 | +0.1 % | +0.9 % | −1.1 % |
| 4: 32 pats m=4 Slim | 4546 / 4713 | +0.1 % | +0.2 % | −1.2 % |
| 5: 40 pats m=3 Fat | 6457 / 6570 | +0.6 % | −0.5 % | +0.1 % |
| 6: 64 pats m=4 Fat | 8345 / 8388 | +0.0 % | −0.0 % | +1.3 % |
| 7: find_iter 3 words | 25403 / 28779 | +9.3 % | +10.5 % | +8.5 % |

In cache, NVOL ties or wins and executes fewer instructions in every case. At 1 MiB or more,
memory dominates. Repeated with 256 KiB, 1 MiB and 4 MiB, case 3 gives −0.4 %, +1.7 % and −2.0 %.
Cases 0 and 4 run the same loop and still disagree with each other (+2.4 % and −0.5 % with 4 MiB).
The hot loop matches the aho-corasick one instruction for instruction. NVOL also reads the loop
bound from the stack, because the verification inlined four times takes up the general registers.
Moving `verify64` out of line frees them, but then each block with candidates reloads 10 `ymm`
registers: −10 to −13 % in cases 3 and 5, rejected.

```sh
rustup target add x86_64-unknown-linux-musl
cd harness/rust
CARGO_TARGET_X86_64_UNKNOWN_LINUX_MUSL_LINKER=rust-lld cargo build --release --target x86_64-unknown-linux-musl --bin tedcount
wsl -d Alpine -- sh tedcounters.sh           # perf: apk add perf
```
